# 런타임 제약과 에러

## 클라우드 런타임 사양

| 항목 | 값 |
|---|---|
| OS / CPU | Debian 12 (glibc 2.36), **x86-64** — macOS/Windows/arm64 바이너리 안 돌아감 |
| 사전 설치 | Node.js 24, Python 3.12, bash, tini. 웹서버·빌드도구·ffmpeg·chromium·apt 없음 |
| 시작 | 패키지가 `/app`에 풀리고 `bash /app/start.sh` 포어그라운드 실행 |
| 포트 | `0.0.0.0:3000` |
| 헬스체크 | `GET /`가 90초 안에 500 미만 응답 (200이어야 방문자가 페이지를 봄) |
| 리소스 | 1 vCPU, 1 GB 메모리, 디스크 512 MB (패키지+데이터 공유) |
| 저장 | `$DATA_DIR`(`/data`) 쓰기 가능. **인스턴스 재시작마다 초기화** |
| 인스턴스 | 사이트당 1개 — 메모리/데이터를 모든 요청이 공유 |
| 네트워크 | 아웃바운드 인터넷 O, HTTPS는 앞단 종료(앱엔 plain HTTP), 요청 300초 후 컷 |
| 시크릿 | 주입 없음. `.env`는 패키징 단계에서 거부 |
| 패키지 한도 | ≤ 200 MB (압축) / 400 MB (해제 후), ≤ 20,000 파일, 파일당 ≤ 25 MB, 깊이 ≤ 32 |

## 주요 에러 코드

| 코드 | 의미 | 대응 |
|---|---|---|
| `PACKAGE_CHECK_FAILED` | 스테이지 검사 실패 — 아무것도 생성/업로드 안 됨 | `error.data.problems` 전부 수정 후 재배포 |
| `PACKAGE_INVALID` | 서버 측 패키지 검증 실패 | `logs <deploymentId>` 읽고 스테이지 재구성 |
| `WARMUP_FAILED` | 90초 내 헬스체크 실패 | `logs`에서 시작 로그 확인: 포트 바인딩, 크래시, 포어그라운드 여부 점검 |
| `START_FAILED` (check) | 로컬 검증에서 시작 실패 | `data.log` 읽기 |
| exit 2 | 미인증 | 사용자에게 ZCode 재로그인 요청 |
| exit 3 | 할당량 초과 | 재시도 금지 — 사용자에게 알림 (다음 기간 또는 플랜 업그레이드) |
| 3611/3614 | 표시 이름/접두사가 콘텐츠 심사 실패 | 다른 이름으로 재시도 |
| 3612 | 심사 거절로 오프라인된 사이트에 online 시도 | 콘텐츠 수정 후 재배포 |

## 스테이지에 넣으면 안 되는 것

- `.env`, `.env.*` (`*.example` 제외) — 배포가 거부된다
- `.git/`, `.zcode-site.json`, `.DS_Store`, `__pycache__/` — 자동으로 제거되긴 하지만 넣지 않는다
- 실행되지 않는 소스: 빌드 후 프론트엔드 소스, TS 원본, 테스트, 문서, dev 의존성
- 캐시: `.next/cache`, `node_modules/.cache`, `.turbo`, 가상환경, 로컬 SQLite 개인 데이터
- 로컬 OS용 네이티브 바이너리 (darwin-arm64 등) — 검사가 잡아낸다

## 패키지가 클 때

1. 프로덕션 의존성만 (`--omit=dev`)
2. 프레임워크 self-contained 출력 사용
3. esbuild로 서버 단일 파일 번들 (네이티브 패키지만 external)
4. 로드 안 되는 파일 제거: 타 플랫폼 프리빌트, 의존성의 `docs/`·`test/`·`*.map`
5. 대형 미디어는 외부 호스팅 — 25 MB 넘는 파일은 못 싣는다

그래도 안 들어가면(예: PyTorch, Chromium, 대형 모델 파일) ZCode Sites에서는 실행 불가 — 사용자에게 그렇게 말한다.
